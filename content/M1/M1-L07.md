# Variables de entorno: la memoria oculta de tu terminal

Tu terminal tiene memoria. Y esa memoria decide cómo se ve, cómo responde y qué tan rápido te obedece.

Cuando abres una terminal, Linux no arranca en blanco. Carga un puñado de definiciones que configuran todo tu entorno de trabajo: quién eres, dónde estás, qué comandos existen y cómo se ve el prompt. Esas definiciones viven dentro de las variables de entorno, y aprender a manejarlas te convierte en dueño de tu sistema en lugar de un invitado que solo aprieta botones.

## La shell: tu traductor con el sistema

Antes de tocar variables, necesitas entender dónde viven. Viven en la shell.

La <a class="term" href="/glosario#SHELL">shell</a> es el programa que hace de puente entre tú y el <a class="term" href="/glosario#SISTEMA_OPERATIVO">sistema operativo</a>: tú escribes órdenes, ella las interpreta y le pide al sistema que las ejecute. No es una caja de texto pasiva; es un entorno vivo que guarda configuraciones mientras trabajas. En Kali Linux esa shell es, casi siempre, bash.

Y esas configuraciones que guarda son, justamente, las variables.

## Variables de entorno: pares clave-valor

Una <a class="term" href="/glosario#VARIABLE_ENTORNO">variable de entorno</a> es un par `CLAVE=valor` que la shell consulta para saber cómo comportarse. Algunas que ya viven en tu sistema:

- `HOME` → dónde está tu carpeta personal.
- `USER` → tu nombre de usuario.
- `SHELL` → qué intérprete usas.
- `PATH` → en qué carpetas buscar comandos.

Las variables de entorno siempre van en mayúsculas y se **heredan**: cualquier proceso hijo que nazca de tu shell las recibe automáticamente. Existe también otro tipo, las shell variables (en minúsculas), que solo viven en la sesión donde se crean y no se exportan. Por ahora, concéntrate en las de entorno, que son las que de verdad mueven el sistema.

Para verlas todas, una sola palabra:

```bash
env
```

La terminal escupe una lista larga: `TERM`, `SHELL`, `USER`, `PATH`, `HOME`... todas en mayúsculas, todas con formato `CLAVE=valor`.

## Ver, filtrar y redirigir

El comando `env` muestra solo las de entorno. Pero si quieres ver TODO (variables de entorno, locales, funciones de shell y tus propias definiciones), usas `set`. El problema: `set` produce tanta salida que no cabe en una pantalla.

Aquí entra la <a class="term" href="/glosario#REDIRECCION_PIPES">redirección con pipes</a>. El símbolo `|` toma la salida de un comando y la convierte en la entrada del siguiente. Piensa en una tubería literal: lo que sale por un extremo entra por el otro.

```bash
set | more
```

`more` detiene la salida pantalla por pantalla (Enter avanza línea a línea, `q` sale). Y si buscas algo concreto, filtras con `grep`:

```bash
set | grep HISTSIZE
```

`HISTSIZE` guarda cuántos comandos pasados recuerda tu historial; las flechas arriba y abajo los recuperan. Por defecto suele valer 1000. Importante: `HISTSIZE` no guarda los comandos en sí, solo la **cantidad máxima** que el historial puede contener.

## Cambiar valores (y por qué importa)

Las variables se modifican con una asignación directa, sin espacios alrededor del `=`:

```bash
HISTSIZE=0
```

Ahora tu historial guarda cero comandos. Las flechas ya no recuerdan nada. ¿Por qué querrías hacer eso? Para no dejar rastro, ya sea en tu propia máquina o en un sistema comprometido. La sigilosidad nace de entender variables como esta.

Pero ojo: ese cambio solo vive en la sesión actual. Cierras la terminal y todo vuelve a su valor por defecto. Para empujarlo hacia los procesos hijos y que hereden el cambio, lo exportas:

```bash
export HISTSIZE
```

`export` saca la variable de tu sesión y la hace visible para cualquier proceso nuevo que nazca de ella. Sin `export`, el cambio muere contigo.

Un consejo de cautela: antes de modificar una variable, guarda su valor original. Así siempre puedes deshacer el daño.

```bash
echo $HISTSIZE > ~/valor_original_histsize.txt
set > ~/todo_el_entorno.txt
```

El `>` redirige la salida a un archivo en lugar de a la pantalla. Si rompes algo, tienes el respaldo.

## Tu prompt: la variable PS1

El texto que ves antes de cada comando (`root@kali:~#`) no es fijo. Lo controla la variable `PS1`, que tiene marcadores especiales:

- `\u` → nombre de usuario actual.
- `\h` → hostname.
- `\w` → directorio actual.

Puedes personalizarla:

```bash
PS1="World's Best Hacker: # "
```

O hacer que parezca una consola de Windows, manteniendo el directorio visible:

```bash
export PS1='C:\w> '
```

Esto es práctico cuando manejas varias máquinas o varias cuentas a la vez: de un vistazo sabes quién eres y dónde estás. Recuerda que hasta que no hagas `export`, el cambio solo afecta a esa terminal.

## PATH: la variable que más te va a doler

`PATH` dice dónde busca la shell los comandos que escribes. Cuando tipeas `ls`, la shell recorre cada carpeta de `PATH` hasta encontrarlo; si no lo halla en ninguna, te escupe `command not found`, aunque el comando exista en otra parte. Mírala:

```bash
echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

El `$` pide "el contenido de la variable", no la palabra literal. Las carpetas van separadas por dos puntos.

Si instalas una herramienta nueva en `/root/newhackingtool`, no podrás ejecutarla desde otra carpeta porque esa ruta no está en `PATH`. La agregas así:

```bash
PATH=$PATH:/root/newhackingtool
```

Fíjate en el `$PATH` a la derecha: significa "lo que ya tenía, MÁS la nueva carpeta". Si olvidas el `$PATH` y escribes solo `PATH=/root/newhackingtool`, borras todo lo demás. Tu sistema pierde acceso a `ls`, `grep`, `cat`... un desastre. Regla de oro: **siempre agregas, nunca reemplazas**. Y si dudas, guarda el valor antes de tocarlo.

## Tus propias variables

Puedes inventar variables. Útil para scripts o para comandos largos que te cansan de escribir:

```bash
MYNEWVARIABLE="Hacking is the most valuable skill of the 21st century"
echo $MYNEWVARIABLE
```

El `$` revela el contenido; sin él, `echo` imprimiría el nombre literal. Como cualquier variable, debes exportarla si quieres que sobreviva a nuevas sesiones.

Y si quieres borrarla, `unset`:

```bash
unset MYNEWVARIABLE
echo $MYNEWVARIABLE
```

La segunda línea devuelve una línea vacía: la variable dejó de existir. Piénsalo dos veces antes de hacer `unset` sobre una variable del sistema, porque tu entorno puede comportarse de forma muy rara después.

---

Las variables de entorno son la configuración invisible de Linux. Dominarlas te da control sobre cómo se ve y cómo se comporta tu sistema y, en algunos casos, cómo desaparecer sin dejar rastro. Pero una variable sola es estática: define, no actúa. En la próxima lección vas a empezar a encadenar comandos dentro de scripts de bash, secuencias que toman todo este poder y lo vuelven automático y repetible.

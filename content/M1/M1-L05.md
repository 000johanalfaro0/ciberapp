# Permisos: quién puede tocar tus archivos

En Linux, no todos pueden tocar todo.

Imagina un edificio de oficinas. Cada empleado tiene la llave de su escritorio, su equipo comparte la sala de reuniones, pero solo el administrador abre el sótano. Linux funciona igual: cada archivo y carpeta decide quién puede leerlo, quién puede modificarlo y quién puede ejecutarlo. Ese control de acceso son los <a class="term" href="/glosario#permisos_rwx">permisos rwx</a>, y dominarlos es saber quién tiene poder sobre cada byte del sistema.

## Tres identidades, tres permisos

Linux no pregunta "¿quién eres?" de forma abstracta. Clasifica a cualquiera que toca un archivo en una de tres identidades, concepto que junto con los grupos forma la base de los <a class="term" href="/glosario#usuarios_grupos">usuarios y grupos</a>:

- **Dueño (owner):** el usuario que creó el archivo.
- **Grupo (group):** un conjunto de usuarios con necesidades similares.
- **Otros (others):** el resto del mundo.

Y para cada identidad existen tres permisos, siempre en ese orden: **r** (read, leer), **w** (write, modificar) y **x** (execute, ejecutar). Un guion `-` donde iría una letra significa "permiso denegado".

Hay un usuario especial: **root**. Root lo puede todo. Es el administrador que abre cualquier puerta, pertenece por defecto al grupo `root` y puede cambiar cualquier permiso de cualquier archivo. Los usuarios comunes se agrupan —`finance`, `developers`, `security`— para heredar permisos en bloque, en vez de configurarlos uno por uno. Así, administrar seguridad es manejable.

## Cómo leer los permisos: `ls -l`

Para ver los permisos de un archivo usa el comando `ls` con el modificador `-l` (long):

```
kali > ls -l
-rw-r--r-- 1 root root 33685504 June 28 2018 hashcat.hcstat
```

Esa sopa de letras a la izquierda es lo que importa. Descompongámosla.

El primer carácter indica el **tipo**: `d` es directorio, `-` es archivo. Después vienen tres grupos de tres letras:

1. `rw-` → permisos del **dueño**: leer y escribir, no ejecutar.
2. `r--` → permisos del **grupo**: solo leer.
3. `r--` → permisos de **otros**: solo leer.

El resto de la línea te dice cuántos enlaces hay, quién es el dueño, qué grupo, el tamaño en bytes, la fecha y el nombre.

## Cambiar dueño y grupo: `chown` y `chgrp`

Para transferir la propiedad de un archivo a otro usuario usa `chown` (change owner):

```
kali > chown bob /tmp/bobsfile
```

Ahora `bob` es el dueño y controla los permisos del archivo. Para cambiar el grupo dueño usa `chgrp` (change group):

```
kali > chgrp security newIDS
```

Es útil cuando, por ejemplo, el grupo `root` instala una herramienta pero quiere que el grupo `security` la administre. En un pentest real, separar a atacantes y defensores en grupos distintos evita que unos pisen el trabajo de los otros.

## Cambiar permisos: `chmod`

Solo root o el dueño pueden cambiar permisos, con `chmod` (change mode). Hay dos formas de hacerlo.

### Método octal

Los permisos son interruptores encendidos o apagados, así que viven en <a class="term" href="/glosario#octal">binario</a>. Tres permisos `rwx` completos son `111`. Una tríada binaria se comprime en un dígito **octal** (base 8, del 0 al 7), así:

| Binario | Octal | rwx  |
|---------|-------|------|
| 000     | 0     | ---  |
| 001     | 1     | --x  |
| 010     | 2     | -w-  |
| 011     | 3     | -wx  |
| 100     | 4     | r--  |
| 101     | 5     | r-x  |
| 110     | 6     | rw-  |
| 111     | 7     | rwx  |

Cada permiso vale: `r=4`, `w=2`, `x=1`, y se suman. Por eso `7` (4+2+1) es "todo permitido". Para fijar los permisos de dueño, grupo y otros de golpe pasas tres dígitos a `chmod`:

```
kali > chmod 774 hashcat.hcstat
```

Dueño `7` (todo), grupo `7` (todo), otros `4` (solo lectura). Es el método más usado en Linux.

### Método UGO (simbólico)

Si los números te marean, existe la sintaxis simbólica, llamada UGO por **u**ser, **g**roup, **o**thers. Indicas a quién, qué operador aplicar y qué permiso:

- `+` añade, `-` quita, `=` fija exacto.

```
kali > chmod u-w hashcat.hcstat
kali > chmod u+x,o+x hashcat.hcstat
```

La primera quita escritura al dueño. La segunda da ejecución al dueño y a otros a la vez. Ambos métodos logran lo mismo; usa el que te fluya.

## Por qué no puedes ejecutar nada recién descargado

Linux asigna por defecto `666` a los archivos y `777` a los directorios. Fíjate: ningún bit de ejecución. Por eso, al bajar una herramienta nueva, recibirás un "Permission denied" si intentas correrla. No es un error, es seguridad: Linux no confía en lo que acabas de traer a casa.

Para poder ejecutarla, te das permiso tú mismo:

```
kali > chmod 766 newhackertool
```

Ahora el dueño puede ejecutarla (`7`), mientras grupo y otros siguen sin poder hacerlo (`6`).

## Endurecer los defaults con `umask`

Si `666` y `777` te parecen demasiado generosos, puedes restar permisos por defecto con el **umask** (user file-creation mask). Es una resta: permiso final = base − umask.

Con un `umask 022`, un archivo nuevo baja de `666` a `644` (dueño lee y escribe, el resto solo lee) y un directorio baja de `777` a `755`. Así viene Kali y casi cualquier Debian de fábrica. Lo ves con el comando `umask` y lo cambias por usuario editando `~/.profile` —por ejemplo, `umask 007` deja todo fuera salvo el dueño y su grupo.

## Permisos especiales: SUID, SGID y sticky bit

Hay tres permisos extra que conceden privilegios temporales y son más delicados.

**SUID** (set user ID): cuando se activa, cualquier usuario ejecuta el archivo **con los privilegios del dueño**, no con los suyos. Se representa con un `4` antes de los permisos (`chmod 4644`) y en el listado largo aparece una `s` donde iría la `x` del dueño.

**SGID** (set group ID): igual, pero con el grupo del dueño. Se pone con un `2` inicial (`chmod 2644`). En directorios tiene otro efecto: los archivos nuevos heredan el grupo del directorio en vez del grupo del creador, ideal para carpetas compartidas entre varios usuarios.

**Sticky bit:** un legado de Unix antiguo. En Linux moderno se ignora, pero oirás el término y conviene conocerlo.

## La grieta que el hacker busca: escalada de privilegios

Aquí viene la parte oscura. Un usuario normal que consigue privilegios de root gana el control total del sistema. Eso se llama <a class="term" href="/glosario#escalada_de_privilegios">escalada de privilegios</a>, y los bits SUID son una puerta clásica.

Piénsalo: si un programa tiene SUID y es del root, quien lo ejecute correrá **como root** durante ese instante. Programas como `sudo`, `passwd` o `gpasswd` lo necesitan para tocar `/etc/shadow`, el archivo donde Linux guarda los hashes de contraseñas. Si un atacante se apodera de uno de esos programas o abusa de un SUID mal configurado, escala hasta root.

Para cazar archivos con SUID en todo el sistema:

```
kali > find / -user root -perm -4000
```

El `-4000` filtra por el bit SUID. Revisa cada línea de la salida: cada archivo es un candidato a vector de ataque. Para el SGID, el filtro equivalente es `-2000`.

---

Los permisos son la primera frontera entre un sistema seguro y uno comprometido. Saber leerlos, cambiarlos y buscar sus puntos débiles te da el control, tanto para defender como para atacar.

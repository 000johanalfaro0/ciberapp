# Dispositivos y almacenamiento en Linux

En Linux, tu disco no es la letra `C:`. Es un archivo.

Windows te vende la ilusión de que cada disco es una letra mágica: `C:`, `D:`, `E:`. Linux hace otra cosa, y al principio parece rara: cada dispositivo conectado —disco, pendrive, mouse— se representa como un archivo dentro del mismo árbol que ya conoces, el que empieza en `/`. Para un hacker esto no es un detalle curioso, es clave. Necesitas saber qué hay enchufado, dónde están los archivos críticos y cómo adjuntar un disco nuevo. Empecemos por el directorio que guarda todos esos dispositivos.

## El directorio `/dev`: todo es un archivo

Linux tiene un directorio especial llamado `/dev` (de *device*, dispositivo). Abre una terminal y haz un listado largo:

```bash
kali > cd /dev
kali > ls -l
```

Verás algo así:

```
crw-------  1  root root  10, 175  May 16  12:44 agpgart
brw-rw----  1  root root   8,   0  May 16  12:44 sda
brw-rw----  1  root root   8,   1  May 16  12:44 sda1
lrwxrwxrwx  1  root root        3  May 16  12:44 cdrom -> sr0
```

Cada dispositivo físico o lógico tiene su propio archivo aquí. El mouse, el teclado, el disco, la lectora de DVD: todos viven como entradas en `/dev`. No importa si los usas o no, el archivo está esperándote.

### Carácter o bloque: la primera letra lo dice

Fíjate en la primera columna de cada línea. Algunas arrancan con `c` y otras con `b`. Esa letra define cómo el dispositivo transfiere datos.

Los **dispositivos de carácter** (`c`) mandan y reciben la información de a un byte por vez. Ejemplos: mouse, teclado. No necesitan velocidad, necesitan precisión.

Los <a class="term" href="/glosario#DISPOSITIVO_BLOQUE">dispositivos de bloque</a> (`b`) mueven datos en bloques enteros, muchos bytes juntos. Ejemplos: discos rígidos, lectoras de DVD. Necesitan alto caudal, no respuesta carácter por carácter. Esa `b` al lado de `sda` ya te avisa de qué clase de dispositivo se trata antes de leer nada más.

## Cómo se nombra un disco

Linux usa etiquetas lógicas para los discos, y estas etiquetas cambian según dónde y cuándo se montan. El mismo disco puede llamarse distinto en distintos momentos.

Históricamente, las disqueteras eran `fd0` y los discos IDE o E-IDE eran `hda`. Hoy casi no se ven. Los discos modernos con interfaz <a class="term" href="/glosario#SATA">SATA</a> o SCSI se llaman `sda`. Cuando hay más de un disco, Linux suma letras en orden alfabético: el primero es `sda`, el segundo `sdb`, el tercero `sdc` y así siguiendo. Esa letra después de `sd` se llama *major number*.

### Particiones: cortar el disco en tajos

Un disco se puede dividir en <a class="term" href="/glosario#PARTICION">particiones</a> para separar la información. Por ejemplo, podrías querer el directorio `/`, el `/home` y la memoria de intercambio cada uno en su partición. Las particiones se numeran con un *minor number* después de la letra del disco. La primera partición del primer disco SATA es `sda1`, la segunda `sda2`, la tercera `sda3`.

Para ver todas las particiones de todos los discos usa `fdisk -l`:

```bash
kali > fdisk -l
```

Ahí aparece cada disco con su tamaño y tipo. Suele haber una partición *swap* (intercambio) que funciona como RAM virtual cuando la memoria real se llena. En el listado también aparece el tipo de sistema de archivos. Linux usa por defecto la familia `ext` (`ext2`, `ext3`, `ext4`, siendo `ext4` el más moderno). Pero vas a encontrar otros: `NTFS`, `FAT`, `HPFS` y `exFAT` son de Windows y macOS. Reconocer el tipo te dice en qué máquina se formateó ese disco: información valiosísima en una investigación.

## Ver dispositivos en árbol con `lsblk`

El comando `lsblk` (*list block*) muestra cada dispositivo de bloque con sus particiones como ramas, en forma de árbol, y no pide permisos de administrador:

```bash
kali > lsblk
```

Aquí aparece `sda` con sus particiones `sda1`, `sda2` y `sda5` indentadas, y una columna `MOUNTPOINT` que indica dónde se adjuntó cada una al árbol de directorios. Esa posición de conexión es el **punto de montaje**.

## Montar y desmontar: el corazón del asunto

Conectar un disco físicamente no alcanza. El dispositivo también tiene que quedar lógicamente adjuntado al sistema de archivos para que sus datos sean accesibles. Esa operación se llama <a class="term" href="/glosario#MONTAJE">montaje</a>.

El nombre viene de los albores de la computación, cuando las cintas magnéticas se montaban físicamente en las unidades. Hoy es un gesto lógico, pero conserva el término.

### Los puntos de montaje: `/mnt` y `/media`

Los puntos de montaje más comunes son dos: `/mnt` y `/media`. Por convención, los dispositivos USB que montas a mano van en `/mnt`, mientras que los que el sistema monta automáticamente van en `/media`. Técnicamente puedes usar cualquier directorio.

Para montar un disco a mano usas `mount`:

```bash
kali > mount /dev/sdb1 /mnt
```

Una advertencia importante: el punto de montaje debería ser un directorio vacío. Si montas sobre un directorio que ya tiene archivos, el dispositivo montado los tapa y quedan invisibles mientras esté montado. Los discos que se montan solos al arrancar el sistema están listados en `/etc/fstab` (*filesystem table*), un archivo que Linux lee en cada arranque.

### Desmontar con `umount`

Para sacar un pendrive sin romper archivos, lo desmontas. El comando es `umount` —ojo, sin la `n`— seguido del archivo de dispositivo:

```bash
kali > umount /dev/sdb1
```

No puedes desmontar un dispositivo ocupado. Si el sistema está leyendo o escribiendo ahí, recibes un error.

## Monitorear y reparar discos

Los discos fallan. Saber revisarlos es una habilidad de administrador y de hacker.

### Espacio libre con `df`

`df` (*disk free*) te dice cuánto espacio se usa y cuánto queda en cada disco montado:

```bash
kali > df
```

Por defecto los tamaños vienen en bloques de 1 KB. Si quieres ver un disco en particular, agrégalo: `df sdb`.

### Errores con `fsck`

`fsck` (*filesystem check*) busca errores y los repara si puede, o aísla los sectores dañados en una tabla de bloques malos. Le pasas el dispositivo a revisar:

```bash
kali > fsck -p /dev/sdb1
```

La opción `-p` repara automáticamente. Pero hay una regla dura: **siempre desmonta el dispositivo antes de revisarlo**. Si está montado, `fsck` se niega a seguir para no romper datos.

## Repaso: qué significa `sda1`

Desglosemos `sda1`, porque lo vas a ver mil veces:

- `sd` → disco SATA/SCSI
- `a` → primer disco del sistema
- `1` → primera partición de ese disco

Si vieras `sdc3`, sería: tercer disco (`c`), tercera partición (`3`). Con esa lógica lees cualquier dispositivo de Linux.

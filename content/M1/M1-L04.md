# Linux: la casa del hacker

No hay hacking serio sin Linux. Punto.

En las lecciones anteriores viste cómo funciona una computadora por dentro: electricidad, bits, CPU, RAM, disco. Ahora vamos a ponerle un director de orquesta encima: el <a class="term" href="/glosario#SISTEMA_OPERATIVO">sistema operativo</a>. Y te explico por qué, si quieres dedicarte a la seguridad informática, ese sistema operativo se llama Linux.

## Por qué los hackers eligen Linux

Cinco razones, todas concretas.

**Es de código abierto.** El código fuente de Linux está disponible: puedes leerlo, copiarlo y modificarlo. Windows no te deja. Si tu objetivo es hacer que un sistema funcione de formas para las que no fue diseñado, poder tocar el código fuente es esencial.

**Es transparente.** Linux te deja ver cada pieza en funcionamiento. Windows es una caja negra: Microsoft hace todo lo posible para que no sepas qué pasa debajo del capó. En Linux tienes un foco encendido sobre cada componente. Y para hackear necesitas entender tu sistema, no adivinarlo.

**Es granular.** En Windows controlas solo lo que Microsoft te permite. En Linux todo se puede controlar desde la <a class="term" href="/glosario#SHELL">shell</a>, desde el detalle más pequeño hasta el nivel más alto.

**Casi todas las herramientas de hacking están hechas para Linux.** Más del 90%. Las excepciones (como Cain y Abel o Wikto) confirman la regla. Incluso cuando herramientas como Metasploit o nmap se adaptan a Windows, no todas sus capacidades se transfieren.

**El futuro le pertenece a Linux y Unix.** Dos tercios de los servidores web del mundo corren Linux o Unix. Los routers y switches casi siempre usan un núcleo Linux. El 80% de los móviles también: Android es Linux e iOS es Unix. Microsoft Windows apenas tiene el 7% del mercado móvil.

## Distribuciones: muchos Linux, un mismo corazón

Linus Torvalds creó Linux en 1991 como alternativa de código abierto a Unix. Como no hay una empresa única que lo controle, existen muchas versiones llamadas <a class="term" href="/glosario#DISTRIBUCION">distribuciones</a>. Todas comparten el mismo núcleo —el kernel, que controla CPU, RAM y disco—, pero cada una trae sus propias utilidades, aplicaciones e interfaz gráfica (GNOME, KDE y otras).

Algunas distribuciones conocidas: Debian, Ubuntu, Red Hat, CentOS, Mint, Arch y SUSE. Todas se ven y se sienten un poco distintas porque sirven para públicos distintos.

Kali Linux es la que usaremos. La desarrolló Offensive Security sobre Debian y viene cargada con cientos de herramientas de pentesting preinstaladas. Es el Linux diseñado para hackers.

## Para qué sirve hackear

Antes de instalar nada, un marco claro. El hacking ético —también llamado "white hat"— consiste en infiltrar y explotar un sistema para encontrar sus debilidades y asegurarla mejor. Se divide en dos vertientes.

La primera es el **pentesting**: un hack legal y por encargo. Las organizaciones hacen primero una evaluación de vulnerabilidades, que suele generar muchos falsos positivos (cosas marcadas como vulnerabilidades que en realidad no lo son). Luego el pentester intenta explotar esas vulnerabilidades para confirmar cuáles son reales y cuáles merecen inversión de tiempo y dinero.

La segunda es el **trabajo militar y de inteligencia**: casi todas las naciones hacen espionaje y guerra cibernética. Imagina un conflicto donde hackers acceden a los planes del enemigo y derriban su red eléctrica, sus refinerías o sus sistemas de agua. Eso ya ocurre todos los días.

## Máquinas virtuales: tu laboratorio seguro

No necesitas borrar tu sistema actual para aprender Linux. Una <a class="term" href="/glosario#MAQUINA_VIRTUAL">máquina virtual</a> (VM) es un sistema operativo completo que corre dentro de otro. Puedes seguir usando Windows o macOS como siempre y tener Kali Linux corriendo dentro, en una ventana. Para quien empieza, es la opción más segura para practicar.

Usaremos VirtualBox, de Oracle, que es gratuita y se descarga desde virtualbox.org.

## Poniendo en marcha Kali

Descarga Kali desde kali.org. Si tu CPU es de 64 bits (lo normal hoy), elige la versión de 64 bits. Si es de 32 bits, la de 32 bits. Para Raspberry Pi, tablets o móviles existe una versión ARM (y Kali NetHunter para teléfonos). Puedes bajar por HTTP o por torrent; este último necesita una aplicación como BitTorrent.

**Crear la VM.** En VirtualBox, pulsa "New", ponle un nombre (por ejemplo, "Kali"), elige tipo Linux y versión Debian (64-bit o 32-bit según tu caso).

**RAM.** No le asignes más del 25 % de tu RAM total. Si tienes 16 GB, asigna 4 GB. Si tienes 4 GB (4096 MB), asigna 1 GB. La VM no consume RAM cuando está apagada, pero sí ocupa espacio en disco.

**Disco duro.** Crea un disco virtual de tipo VDI, con asignación dinámica (solo ocupa lo que necesitas, cuando lo necesitas). El tamaño por defecto es 8 GB; te recomiendo entre 20 y 25 GB. Ampliarlo después es complicado, mejor ir con margen.

**Instalar.** Arranca la VM, selecciona la imagen .iso de Kali como disco de arranque y elige instalación gráfica. Te pedirá idioma, ubicación, teclado, hostname (puedes dejar "kali") y dominio (no hace falta poner nada). Luego te pedirá una contraseña para root. Elige una larga y compleja; aunque sea una VM local, adquiere el hábito.

**Particionado.** Elige "Guided - use entire disk" → "All files in one partition" → "Finish partitioning and write changes". Tranquilo: es un disco virtual vacío, no pierdes nada real. En un sistema de producción sí convendría separar /home, /var y /tmp en particiones distintas, pero para aprender no hace falta.

**Detalles finales.** No necesitas network mirror. Di que sí a instalar GRUB (el gestor de arranque, que te deja elegir qué sistema arrancar al encender). Selecciona "Enter device manually" y elige la unidad, probablemente /dev/sda.

Si Kali falla al instalar dentro de VirtualBox, lo más probable es que la virtualización esté desactivada en tu BIOS. Cada equipo es distinto: busca la solución para tu fabricante. En Windows además puede hacer falta desactivar Hyper-V u otro software de virtualización que compita.

Reinicia y entra como root con tu contraseña. Estás dentro.

## Términos que vas a usar desde ya

Memoriza estos conceptos antes de continuar; aparecerán en cada lección.

**Root.** El administrador o superusuario de Linux. Puede hacer casi cualquier cosa: reconfigurar el sistema, añadir usuarios, cambiar contraseñas. Muchas herramientas de hacking exigen que las ejecutes como root.

**Shell.** El entorno y el intérprete donde escribes comandos. Es tu interfaz de texto con el sistema. Vamos a trabajar mucho aquí.

**Binarios.** Archivos que se pueden ejecutar, parecidos a los .exe de Windows. Suelen vivir en /usr/bin o /usr/sbin e incluyen utilidades como ls, cat, ps e ifconfig, además de herramientas como aircrack-ng o el sistema de detección de intrusos Snort.

**Script.** Una serie de comandos que se ejecutan en un intérprete. Muchas herramientas de hacking son simplemente scripts. Se pueden escribir en bash, Python, Perl o Ruby. Python es hoy el más popular entre hackers.

**Sensibilidad a mayúsculas.** A diferencia de Windows, Linux distingue entre Desktop, desktop y DeskTop: son tres cosas distintas. Si recibes "file or directory not found" y estás seguro de que existe, revisa las mayúsculas.

**Directorio.** Lo mismo que una carpeta en Windows. Sirve para organizar archivos en estructura jerárquica.

**Home.** Cada usuario tiene su propio directorio /home, y ahí es donde se guardan tus archivos por defecto.

# Servicios en Linux: programas que trabajan de fondo

Un servicio no se abre. Ya está corriendo, en silencio, esperando que lo necesites.

En Linux, un <a class="term" href="/glosario#servicio">servicio</a> es una aplicación que vive en segundo plano: sin ventana, sin icono, lista para responder en cuanto alguien la llama. Tu sistema trae decenas preinstalados. No los ves, pero están ahí. El más famoso es Apache, que mueve más de la mitad de los servidores del planeta.

En esta lección vas a arrancar, detener y controlar servicios desde la terminal, y vas a tocar tres que importan mucho en seguridad: Apache, OpenSSH y MySQL. El capítulo original nombra también PostgreSQL como cuarto servicio clave, aunque aquí nos concentraremos en los tres que desarrolla en detalle.

## Arrancar, detener y reiniciar

Algunos servicios se controlan con el ratón, como en Windows o Mac. Pero los que de verdad interesan se manejan desde la línea de comandos. La sintaxis base es una sola línea:

```bash
service nombredelservicio start|stop|restart
```

Tres verbos, nada más: `start` para arrancar, `stop` para detener y `restart` para reiniciar. Por ejemplo, para levantar Apache:

```bash
kali > service apache2 start
```

¿Para qué sirve reiniciar? Cuando cambias un archivo de configuración (casi siempre texto plano), el servicio no se entera solo. Hay que reiniciarlo para que cargue los cambios. Es como avisarle a un camarero que cambió el menú: si no le dices, sigue sirviendo el plato viejo.

```bash
kali > service apache2 restart
```

## Apache: tu propio servidor web

Apache es probablemente el servicio más usado en Linux. Está en más del 55 % de los <a class="term" href="/glosario#servidor-web">servidor web</a> del mundo, así que cualquiera que quiera entender o atacar sitios web necesita conocerlo por dentro.

Si usas Kali, ya lo tienes instalado. Si no, lo instalas desde los **repositorios** (los almacenes oficiales de software de tu distribución):

```bash
kali > apt-get install apache2
```

Apache suele ir acompañado de MySQL y de un lenguaje como PHP o Python para crear aplicaciones web. Esa combinación —Linux, Apache, MySQL y PHP/Python— se conoce como **LAMP** (en Windows le dicen WAMP). Es la base sobre la que se construyen gran parte de los sitios web.

Para comprobar que funciona, abre el navegador y entra a `http://localhost/`. `localhost` es la forma de decir "esta misma máquina". Deberías ver una página que dice **"It works"**: es la página por defecto.

## Editar la página por defecto

Esa página vive en un archivo: `/var/www/html/index.html`. Si quieres que tu servidor muestre otra cosa, solo tienes que editar o reemplazar ese archivo con cualquier editor de texto. Verás código **HTML**: etiquetas que contienen, en formato de marcado, el mismo texto que apareció en el navegador. Basta con sustituirlo.

Un ejemplo mínimo:

```html
<html>
<body>
<h1>¡raíz_ es lo mejor!</h1>
<p>Si quieres aprender ciberseguridad, este es el lugar.</p>
</body>
</html>
```

Guarda ese contenido como `/var/www/html/index.html` (sobrescribe el anterior) y recarga `http://localhost` en el navegador. Apache ya está sirviendo tu propia página.

## OpenSSH: controlar máquinas a distancia

<a class="term" href="/glosario#ssh">SSH</a> significa *Secure Shell* y sirve para conectarte de forma segura a la terminal de una máquina remota, cifrando la comunicación y pidiendo contraseña. Vino a reemplazar a **telnet**, el protocolo antiguo que viajaba en texto plano y que cualquiera podía espiar en la red.

El servicio más usado en Linux es **OpenSSH**, que viene casi en todas las distribuciones. Los administradores lo usan para gestionar servidores a distancia; y sí, también es la herramienta clásica para conectarse a un sistema comprometido. La idea es la misma: controlas una máquina como si tuvieras su teclado enfrente, pero desde otra red.

Para arrancarlo:

```bash
kali > service ssh start
```

Para conectarte a otra máquina necesitas un usuario válido y su dirección IP:

```bash
kali > ssh pi@192.168.1.101
```

Te pedirá la contraseña. Si aciertas, tendrás una terminal de esa máquina remota dentro de la tuya. Desde ahí puedes ejecutar comandos como si estuvieras delante de ella.

### El "Raspberry Spy Pi"

Una Raspberry Pi es un ordenador del tamaño de una tarjeta de crédito, ideal como dispositivo de vigilancia remota. Si le añades un módulo de cámara y la conectas por Wi-Fi a la red local, puedes controlarla por SSH y tomar fotos a distancia sin tocarla.

Tras habilitar y arrancar SSH en la Pi (`service ssh start`) y descubrir su IP con el comando `ifconfig`, te conectas desde tu Kali como ya vimos. Luego, con la cámara activada desde la herramienta de configuración (`sudo raspi-config`), tomas una foto así:

```bash
pi@raspberrypi > raspistill -v -o primerafoto.jpg
```

La opción `-v` da salida detallada y `-o` indica el nombre del archivo. Un `ls -l` te confirma que la imagen ya está guardada en la Pi. Acabas de espiar a distancia usando solo la terminal.

## MySQL y MariaDB: donde vive la información

Aquí está el premio gordo. Casi todos los sitios web modernos guardan sus datos en una <a class="term" href="/glosario#base-de-datos">base de datos</a>: usuarios, contraseñas, tarjetas de crédito, mensajes. Por eso, cuando alguien ataca un sitio, casi siempre busca llegar hasta aquí.

MySQL es la base de datos más usada detrás de las aplicaciones web. **MariaDB** es una variante (un *fork*) nacida para garantizar que el software siga siendo libre después de que Oracle comprara MySQL. En la práctica, los comandos que verás sirven para ambas.

Para arrancar el servicio:

```bash
kali > service mysql start
```

Y para entrar, te conectas como usuario `root`:

```bash
kali > mysql -u root -p
```

Ojo: en la configuración por defecto, la contraseña de `root` en MySQL viene **vacía**. Eso es un agujero de seguridad enorme. Lo primero que deberías hacer al entrar es ponerle una clave. Además, los usuarios y contraseñas de MySQL son independientes de los de tu sistema Linux: tienen su propio mundo separado.

## Hablar con la base de datos: SQL

Para pedirle cosas a la base de datos usas **SQL**, un lenguaje de consulta pensado para bases de datos relacionales, donde la información se guarda en **tablas** de filas y columnas que se relacionan entre sí.

Algunos comandos básicos:

| Comando | Para qué sirve |
|---------|----------------|
| `select` | Recuperar datos |
| `union` | Combinar resultados de varios `select` |
| `insert` | Añadir datos nuevos |
| `update` | Modificar datos existentes |
| `delete` | Borrar datos |

Por ejemplo, para ver el usuario y la contraseña de quien se llama `admin`:

```sql
select user, password from customers where user='admin';
```

**Todos los comandos de MySQL terminan en punto y coma (`;`).** Si lo olvidas, la consola se queda esperando a que termines la frase.

## Ponerle contraseña a root y explorar

Primero, mira qué usuarios hay:

```sql
mysql > select user, host, password from mysql.user;
```

Para ver qué bases de datos existen:

```sql
mysql > show databases;
```

MySQL trae tres por defecto (`information_schema`, `mysql` y `performance_schema`). Para empezar a usar una, escribe `use mysql;`. Y para asignarle contraseña a `root`:

```sql
mysql > update user set password = PASSWORD("tu_clave") where user = 'root';
```

Si el servidor está en otra máquina, le indicas su IP al conectarte:

```bash
kali > mysql -u root -p 192.168.1.101
```

Ya dentro, vuelves a listar bases de datos con `show databases;`. Si encuentras una interesante (digamos, `creditcardnumbers`), te conectas con `use creditcardnumbers;` y exploras sus tablas con `show tables;`. Dentro de cada tabla están los datos, listos para un `select`. Un administrador rara vez llamará a una base "creditcardnumbers" tan a las claras, así que parte del trabajo será husmear hasta dar con la que importa.

## Nota final

Linux no es solo un sistema de archivos y comandos: es una plataforma que mantiene servicios vivos en segundo plano, y cada servicio es una puerta. Apache abre una puerta web, SSH una puerta de control remoto y MySQL una puerta directa al tesoro de los datos. En la próxima lección vas a aprender a vigilar quién pasa por esas puertas: cómo ver, cerrar y controlar los procesos y conexiones que mantienen a tu sistema con vida.

# Tu primera caja de herramientas

En Linux, casi todo lo que tocas es un archivo de texto.

Los archivos de configuración, los registros del sistema y las listas de reglas son texto plano. Para reconfigurar una aplicación solo abres su archivo, cambias unas palabras, guardas y reinicias: el cambio queda hecho. El control del sistema entero vive en archivos legibles. Por eso, manipular texto es la habilidad más rentable que puedes aprender.

Para eso se usan los **comandos**. Un <a class="term" href="/glosario#COMANDO">comando</a> es una orden que escribes en la <a class="term" href="/glosario#SHELL">shell</a> —la terminal donde te comunicas con el sistema— para que haga algo concreto: mostrar un archivo, buscar una palabra o reemplazar texto. Imagina un taller de herramientas: cada comando tiene su función y, al combinarlos, resuelves casi cualquier tarea.

A lo largo de la lección usaremos como ejemplo el archivo de configuración de Snort, un sistema de detección de intrusos. Es un archivo largo (más de 600 líneas), ideal para entender por qué necesitas más que un solo comando.

## Ver un archivo entero: `cat`

El comando más básico es `cat`, que vuelca todo el contenido en la pantalla:

```
cat /etc/snort/snort.conf
```

El problema es que `cat` no se detiene: el texto pasa rápido hasta el final. Para un archivo de cientos de líneas resulta casi inútil. Por eso existen herramientas más precisas.

## Ver solo el principio o el final: `head` y `tail`

`head` muestra, por defecto, las primeras 10 líneas:

```
head /etc/snort/snort.conf
```

Si quieres otra cantidad, usas el modificador `-` seguido del número:

```
head -20 /etc/snort/snort.conf
```

`tail` hace lo mismo con el final del archivo. Por defecto entrega las últimas 10 líneas y acepta el mismo modificador:

```
tail -20 /etc/snort/snort.conf
```

Estos dos comandos son perfectos para echar un vistazo rápido sin que el texto te inunde.

## Numerar líneas: `nl`

En archivos largos conviene tener números de línea para referenciar puntos concretos. El comando `nl` los añade:

```
nl /etc/snort/snort.conf
```

Cada línea aparece con su número, lo que facilita volver al mismo sitio. Ojo: `nl` no numera las líneas en blanco.

## Filtrar texto: `grep`

`grep` es, probablemente, el comando de texto más usado. Busca las líneas que contienen una palabra o patrón y muestra solo esas. Para ver todas las líneas de Snort que mencionan `output`:

```
cat /etc/snort/snort.conf | grep output
```

Aquí aparece una idea clave: la <a class="term" href="/glosario#PIPE">pipe</a> (o tubería), escrita con el carácter `|`. La pipe toma la salida de un comando y la usa como entrada del siguiente. Es como una manguera que conecta dos herramientas: lo que sale de `cat` entra en `grep`. Gracias a las pipes, los comandos simples se convierten en *pipelines* potentes.

## Buscar y reemplazar: `sed`

`sed` (de *stream editor*) funciona como el buscar y reemplazar de un editor de texto. Para cambiar cada aparición de `mysql` por `MySQL` en todo el archivo:

```
sed s/mysql/MySQL/g /etc/snort/snort.conf > snort2.conf
```

La `s` indica sustitución; entre barras pones primero lo que buscas y luego con qué lo reemplazas. La `g` final significa *global*: cambia todas las apariciones de cada línea, no solo la primera.

El símbolo `>` es la <a class="term" href="/glosario#REDIRECCION">redirección</a>: envía el resultado a un archivo nuevo (`snort2.conf`) en lugar de mostrarlo en pantalla.

Sin la `g`, `sed` reemplazaría solo la primera aparición de cada línea. Y si pones un número al final, como `s/mysql/MySQL/2`, cambia únicamente la segunda aparición de cada línea. Tienes control fino sobre cada reemplazo.

## Navegar archivos largos: `more` y `less`

`more` muestra el archivo una página a la vez. Pulsas Enter para avanzar y `q` para salir:

```
more /etc/snort/snort.conf
```

En la esquina inferior verás qué porcentaje del archivo has recorrido.

`less` hace lo mismo y algo más: puedes buscar dentro del archivo. Pulsa `/` seguido de la palabra y salta a la primera coincidencia, resaltada; con `n` avanzas a la siguiente. Por eso se bromea con que *less is more*.

```
less /etc/snort/snort.conf
```

## Combinar herramientas: el desafío

El verdadero poder aparece cuando encadenas comandos. Supón que quieres ver las cinco líneas anteriores a la que dice `# Step #6: Configure output plugins`.

Primero, numera las líneas y filtra para localizarla:

```
nl /etc/snort/snort.conf | grep output
```

Descubres que esa línea es la 512. Quieres las líneas 507 a 512. Lo resuelves encadenando `tail` y `head`:

```
tail -n+507 /etc/snort/snort.conf | head -n 6
```

`tail -n+507` empieza desde la línea 507 y `head -n 6` se queda con las seis primeras de ese trozo. Dos comandos simples, un resultado preciso. Esa es la filosofía de Linux: herramientas pequeñas que brillan al combinarse.

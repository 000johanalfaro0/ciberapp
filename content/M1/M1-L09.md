# Comprimir y archivar en Linux

Un archivo grande tarda más en viajar. Y muchos archivos sueltos son difíciles de mover.

En Linux existen herramientas para juntar varios archivos en uno solo y, además, reducir su tamaño. Vamos a ver cómo empaquetar, cómo comprimir y cómo copiar dispositivos enteros bit por bit.

## ¿Qué es la compresión?

La <a class="term" href="/glosario#compresion">compresión</a> reduce el tamaño de los datos. Así ocupan menos espacio y se transmiten más rápido.

Existen dos familias. La **compresión con pérdida** (lossy) logra archivos mucho más chicos, pero pierde información: el resultado no es idéntico al original. Funciona bien para imágenes, video y audio, donde el ojo o el oído apenas notan la diferencia. Los formatos `.mp3`, `.mp4` y `.jpg` son ejemplos. Un audiófilo dirá que nota la diferencia entre un `.mp3` y un `.flac` sin comprimir, y tiene razón: ahí está el tradeoff.

La **compresión sin pérdida** (lossless) conserva cada bit original. Al descomprimir, recuperas exactamente el archivo inicial. Es menos eficiente y comprime menos, pero para scripts, documentos o software la integridad es innegociable. Esta lección se enfoca en esta familia.

Una analogía: la compresión con pérdida es como resumir un libro con tus palabras; pierdes el texto exacto pero conservas la idea. La compresión sin pérdida es como un acordeón que se pliega y se despliega sin perder ni una nota.

## Juntar archivos con tar

Antes de comprimir, conviene agrupar varios archivos en uno solo. Para eso se usa <a class="term" href="/glosario#tar">tar</a>, cuyo nombre viene de *tape archive*, un recuerdo de la época en que los datos vivían en cintas magnéticas. El archivo resultante se llama <a class="term" href="/glosario#tarball">tarball</a>.

Para crear un tarball con tres scripts:

```bash
tar -cvf HackersArise.tar hackersarise1 hackersarise2 hackersarise3
```

Los flags significan:

- `-c`: crear (*create*).
- `-v`: verboso, lista los archivos mientras trabaja (opcional).
- `-f`: escribir en el archivo cuyo nombre sigue a continuación.

Atención: archivar **no** comprime. De hecho, el tarball puede pesar un poco más que la suma de los archivos originales, porque `tar` agrega metadatos. Con archivos chicos ese sobrepeso se nota; con archivos grandes, se diluye.

Para ver el contenido sin extraerlo, se usa `-t` (*list*):

```bash
tar -tvf HackersArise.tar
```

Para extraer, se usa `-x` (*extract*):

```bash
tar -xvf HackersArise.tar
```

Si quitas el `-v`, la extracción es silenciosa. Por defecto, si un archivo extraído ya existe, `tar` lo reemplaza.

## Comprimir el tarball

Una vez que tienes el tarball, lo comprimes. Linux ofrece varias herramientas; veremos tres. Cada una usa un algoritmo distinto y logra un ratio de compresión diferente.

### gzip

<a class="term" href="/glosario#gzip">gzip</a> (GNU zip) es la más común en Linux. Su extensión es `.tar.gz` o `.tgz`:

```bash
gzip HackersArise.*
```

El asterisco (`*`) es un comodín: le dice al sistema que aplique el comando a cualquier archivo cuyo nombre empiece con `HackersArise.`, sin importar la extensión. Tras ejecutarlo, el archivo se transforma en `HackersArise.tar.gz` y se reduce drásticamente. Para descomprimir, se usa `gunzip` (*GNU unzip*):

```bash
gunzip HackersArise.*
```

### bzip2

<a class="term" href="/glosario#bzip2">bzip2</a> funciona igual que `gzip`, pero logra archivos aún más chicos a cambio de ser más lento. Su extensión es `.tar.bz2`:

```bash
bzip2 HackersArise.*
bunzip2 HackersArise.*
```

### compress

<a class="term" href="/glosario#compress">compress</a> es el más rápido de los tres, pero el resultado es el más grande. Su extensión es `.tar.Z` (con Z mayúscula):

```bash
compress HackersArise.*
uncompress HackersArise.*
```

Un detalle útil: `gunzip` también puede descomprimir archivos creados con `compress`.

En resumen: `compress` gana en velocidad, `bzip2` gana en tamaño y `gzip` queda en el medio. ¿Por qué conocer las tres? Porque al descargar software de terceros te encontrarás con cualquiera de los tres formatos, y debes saber cómo abrirlos.

## Copia bit a bit con dd

Hay un comando que sobresale en seguridad: <a class="term" href="/glosario#dd">dd</a>. Hace una copia física, bit por bit, de un archivo, un sistema de archivos o un disco entero.

¿La diferencia con una copia normal como `cp`? `dd` copia incluso los archivos borrados que aún flotan en el medio físico. Por eso lo usan los investigadores forenses para preservar evidencia, y también los atacantes para duplicar el disco de un sistema comprometido.

La sintaxis básica es:

```bash
dd if=archivo_entrada of=archivo_salida
```

`if` es *input file* y `of` es *output file*. Por ejemplo, para clonar una memoria USB que el sistema identifica como `/dev/sdb`:

```bash
dd if=/dev/sdb of=/root/copia_usb
```

Dos opciones muy útiles:

- `bs=4096`: define el tamaño de bloque. Por defecto son 512 bytes; subirlo (típicamente al tamaño de sector, 4 KB) acelera la copia.
- `conv=noerror`: sigue copiando aunque encuentre errores de lectura.

Un ejemplo completo:

```bash
dd if=/dev/sdb of=/root/copia_usb bs=4096 conv=noerror
```

Ojo: `dd` es lento. No lo uses para copiar archivos del día a día; resérvalo para cuando necesitas una réplica fiel del medio físico, sin las estructuras lógicas del sistema de archivos.

## Resumen

- `tar` agrupa varios archivos en un tarball (no comprime).
- `gzip`, `bzip2` y `compress` comprimen ese tarball con distintos ratios de velocidad y tamaño.
- `dd` copia bit por bit, incluidos los archivos borrados; es clave en análisis forense.
